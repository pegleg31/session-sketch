Three interface directions, same intake

The same moment in the same Joins intake, rendered three ways. The engine, questions, and scoring do not change between them — only how the faculty member moves through it. Scroll all three, then pick the one to prototype for real.

Direction A

Conversational — one question at a time

Feels like a design conversation, not a form. Each answer is acknowledged before the next question, examples appear inside the question, and typed answers can be gently played back ("so the topic is joins — the unit is databases, yes?").

What it buys
Zero wall-of-form. Every question gets full attention, examples live in-line, and playback ("so the topic is…") catches misreads like the audience question before they poison the result. Closest fit if AI ever moves into the loop — the conversation is already the shape of that.
What it costs
Slowest path through; no skimming ahead; hard to revise an early answer without scrolling history. Faculty can't see how much is left, and a facilitator can't point at the whole page. Most new build effort of the three.
Direction B

Guided wizard + live preview

Keeps the current steps, but the right rail shows the concept taking shape as answers land — which tag is leading, which build slots are filled, what's still missing. The tool's reasoning becomes visible without exposing raw scores to game.

Direction C

Flatter — one page, progressive disclosure

No steps at all. Sections open one at a time on a single page; answered sections collapse to a one-line summary that stays editable. The 18 kinds become a two-step (cluster, then kind) so no screen ever shows more than ~6 choices. Helper text hides behind "why?".
